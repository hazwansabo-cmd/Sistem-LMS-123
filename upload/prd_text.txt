1. Ringkasan Eksekutif

Dokumen ini menggariskan keperluan untuk membangunkan Sistem Pengurusan
Pembelajaran (LMS) berasaskan web bagi Al Amin di Malaysia. LMS ini
menyediakan kursus dan bahan latihan Kecerdasan Buatan (AI) untuk
kakitangan, serta modul kehadiran digital yang menggantikan kerja menaip
data kehadiran secara manual.

Sistem dibina menggunakan React sebagai antara muka pengguna. Pada fasa
prototaip, semua data disimpan dalam pangkalan data dummy (data contoh)
supaya sistem boleh didemonstrasi sepenuhnya tanpa pelayan dan kos
infrastruktur. Struktur data direka supaya boleh disambung kepada
pangkalan data sebenar pada fasa seterusnya tanpa menulis semula antara
muka.

Pembangunan dilakukan melalui z.ai menggunakan model GLM 5.2, dipandu
oleh PRD ini sebagai sumber rujukan tunggal.

2. Latar Belakang dan Pernyataan Masalah

2.1 Latar belakang

Penggunaan AI dalam kerja harian (penulisan, analisis data, pengurusan
dokumen, khidmat pelanggan) kian meluas. Kakitangan memerlukan latihan
berstruktur yang selamat, relevan dengan konteks Malaysia, dan mudah
diikuti mengikut tahap kemahiran masing-masing.

2.2 Pernyataan masalah

-   Kemasukan kehadiran secara manual: Pentadbir terpaksa menaip data
    kehadiran kakitangan satu per satu selepas setiap sesi latihan. Ini
    memakan masa, mudah silap, dan sukar diaudit.

-   Bahan latihan bertaburan: Slaid, video dan nota disimpan di pelbagai
    tempat tanpa satu platform pusat.

-   Tiada penjejakan kemajuan: Pihak pengurusan tidak dapat melihat
    siapa telah menamatkan latihan, skor, dan jurang kemahiran.

-   Pensijilan tidak konsisten: Sijil tamat latihan dikeluarkan secara
    manual dan sukar disahkan.

2.3 Peluang

Satu platform tunggal yang menggabungkan kandungan AI, kuiz, kehadiran
automatik (imbasan QR, kod sesi, import CSV) dan laporan akan
menjimatkan masa pentadbiran dan meningkatkan kualiti latihan.

-   Antara muka React yang responsif (desktop, tablet, telefon)

9.2 Strategi pangkalan data dummy

-   Fail benih (seed) JSON dalam folder /src/mocks/data menyimpan
    pengguna, kursus, sesi dan lain-lain.

-   MSW memintas permintaan HTTP (contoh: GET /api/courses) dan membalas
    daripada IndexedDB; komponen UI menggunakan fetch biasa seolah-olah
    API sebenar wujud.

-   Pada fasa produksi, MSW dimatikan dan URL API diarahkan ke backend
    sebenar (cadangan: Node.js + PostgreSQL atau Supabase) tanpa
    perubahan pada komponen.

-   Butang 'Reset data dummy' mengosongkan IndexedDB dan menyemai semula
    dari fail benih.

-   Semua kata laluan dummy hanyalah untuk demo dan tidak boleh
    digunakan semula di sistem sebenar.

-   Teks Bahasa Malaysia yang ringkas dan jelas; elakkan istilah

-   Tugas kehadiran mesti boleh disiapkan dalam kurang 3 klik oleh staf
    dan kurang 1 minit oleh jurulatih.

-   Reka bentuk mengutamakan telefon bimbit untuk imbasan QR.

12. Aliran Pengguna Utama

12.1 Kehadiran melalui QR (staf)

1. Jurulatih membuka sesi dan memaparkan kod QR pada skrin.

2. Staf membuka LMS di telefon dan memilih 'Daftar Kehadiran'.

3. Staf mengimbas QR; sistem mengesahkan sesi, masa dan pendaftaran
staf.

4. Sistem merekod 'Hadir' atau 'Lewat' dengan cap masa dan kaedah 'QR'.

5. Staf melihat pengesahan; jurulatih melihat senarai dikemas kini
secara langsung.

12.2 Kehadiran manual pukal atau import (Admin/Jurulatih)

1. Pilih sesi dan klik 'Kemasukan Pukal' atau 'Import CSV'.

2. Untuk import: muat naik fail, sistem memadankan nombor staf dan
menunjukkan pratonton serta ralat.

3. Betulkan ralat, sahkan, dan simpan; sistem mencatat kaedah 'import'
dan audit log.

4. Eksport laporan kehadiran jika perlu.

12.3 Menamatkan kursus dan mendapatkan sijil

1. Staf mendaftar atau ditugaskan kursus.

2. Staf menyiapkan pelajaran dan lulus kuiz.

3. Sistem menyemak syarat kehadiran (jika ada).

4. Sijil dijana dengan nombor pengesahan dan notifikasi dihantar.

13. Keselamatan dan Pematuhan (PDPA 2010)

Walaupun fasa prototaip menggunakan data dummy, reka bentuk mesti
bersedia untuk pematuhan Akta Perlindungan Data Peribadi 2010 (PDPA)
Malaysia apabila data sebenar digunakan.

-   Pengumpulan data minimum: hanya data yang perlu (nama, nombor staf,
    jabatan, e-mel).

-   Notis privasi dan persetujuan dipaparkan semasa log masuk pertama.

-   Kawalan akses berasaskan peranan; staf hanya melihat data sendiri.

-   Kata laluan produksi mesti di-hash (bcrypt/argon2) dan sesi
    menggunakan token dengan tempoh luput; tiada rahsia disimpan dalam
    kod hadapan.

-   Perlindungan daripada XSS dan CSRF; validasi input pada semua borang
    dan import fail.

-   Jejak audit untuk perubahan data kehadiran dan sijil.

-   Polisi pengekalan data dan kemudahan padam/anonimkan data pengguna.

-   Kandungan latihan AI mesti mengingatkan staf supaya tidak memasukkan
    data sulit atau peribadi ke dalam alat AI awam.

-   Pemilik data dan penempatan pelayan produksi perlu dinilai
    (pertimbangkan hos di Malaysia atau rantau yang diluluskan).

14. Strategi Pembangunan dengan z.ai (GLM 5.2)

Pembangunan akan menggunakan z.ai dengan model GLM 5.2. Penjanaan kod
oleh AI berfungsi paling baik apabila tugas dipecahkan kepada langkah
kecil, jelas dan boleh disahkan. Cadangan berikut ialah amalan umum;
semak keupayaan dan had terkini model serta platform di z.ai sebelum
bermula.

14.1 Prinsip kerja

-   Gunakan PRD ini sebagai konteks tetap: tampal ringkasan, tindanan
    teknologi dan model data pada permulaan sesi.

-   Bina secara berfasa (satu fitur setiap prompt), jangan minta seluruh
    sistem sekali gus.

-   Setiap prompt menyatakan: matlamat, fail yang terlibat, kriteria
    penerimaan dan larangan (contoh: tiada pustaka tambahan).

-   Minta kod TypeScript lengkap dan boleh dijalankan, bukan potongan
    separa.

-   Selepas setiap fasa: jalankan aplikasi, ujian dan lint; sampaikan
    mesej ralat sebenar kepada model untuk pembetulan.

-   Gunakan kawalan versi (Git) dan komit selepas setiap fasa yang
    berfungsi.

-   Semak semua kod yang dijana secara manual, terutamanya logik
    kehadiran, kebenaran akses dan import fail.

-   Jangan sertakan data peribadi sebenar atau kunci rahsia dalam
    prompt.

17. Kriteria Penerimaan

-   Semua keperluan berkeutamaan 'M' berfungsi tanpa ralat kritikal.

-   Staf boleh daftar kehadiran melalui QR atau kod dalam kurang 30

    mengeksport laporan dalam kurang 1 minit.

-   Import CSV mengesan baris tidak sah dan menunjukkan mesej ralat
    jelas.

-   Setiap perubahan kehadiran direkod dalam log audit.

-   Sijil dijana hanya apabila semua syarat dipenuhi dan boleh disahkan
    melalui halaman awam.

-   Kawalan akses peranan berfungsi: staf tidak boleh mencapai skrin
    Admin.

-   Aplikasi berfungsi dengan baik pada telefon, tablet dan desktop pada
    pelayar yang disenaraikan.

-   Skor Lighthouse kebolehcapaian 90 atau lebih untuk halaman utama.

-   Data dummy boleh direset dan disemai semula dengan satu klik.

18.1 Prompt konteks awal (tampal pada permulaan sesi z.ai)

  Anda ialah jurutera perisian kanan. Bantu saya membina LMS untuk

  Tindanan: React + TypeScript + Vite, Tailwind, shadcn/ui, React

  Peranan: Admin, HR/Pengurus, Jurulatih, Staf.

  Keutamaan: modul kehadiran (QR, kod sesi, kemasukan pukal,

  Peraturan: kod TypeScript lengkap, struktur folder berasaskan fitur,
  tiada pustaka tambahan tanpa kebenaran, semua akses data melalui
  lapisan service, kod mesti lulus lint.

  Saya akan berikan tugas satu demi satu. Sahkan faham, kemudian tunggu
  arahan langkah 1.

18.2 Contoh prompt untuk modul kehadiran (langkah 6)

  Bina fitur 'attendance' dalam src/features/attendance.

  setiap sesi; semua perubahan direkod dalam auditLogs.
